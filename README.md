# ooxml-file

Static web app to open XML-based Office packages (documents, templates, slide shows, add-ins, and themes), browse contents as a tree, edit XML, and repack & download.

## Features

- **Source change details:** Detected disk updates stay pending until you click Reload. The file tree marks modified parts with a diff icon, additions with a green plus, and removals with a red minus and struck-through filename; parent folders indicate updates with a blue dot. Click an update icon to open a read-only diff in the right editor area. Added parts appear as preview-only tree entries and are never included in exports before reloading. Ordinary existing filenames still open the editable loaded version. Local unexported-change dots remain independent. XML diffs support formatted/raw display and change navigation; binary previews show byte sizes. Back to editor restores the mounted editor and its undo, cursor, scroll and folds. Reload prefers the previewed part if it still exists, otherwise the original editor part. Successful reload clears source markers and establishes a fresh baseline; failed reloads retain markers and local edits. An open source diff follows each successfully inspected disk save against the fixed loaded baseline, preserving scroll, selection, search and display preference where possible. Source diff URLs use the same part path with `?view=source-diff`; browser Back/Forward restores the part and view while source snapshots remain in memory. Disk saves do not add history entries. Reload source replaces the current URL with the normal editor path. If comparison snapshots are unavailable after a page reload, the URL falls back to the normal file view. Run `npm run test:routes` for route-history tests. The header labels the comparison “Loaded → Disk · Read-only”; restored parts stay open with a no-change message. Metadata-only saves automatically clear pending status without reloading. The Download button exports the loaded package with local edits; while disk changes are pending or a source diff is open, its tooltip explains that pending disk updates are excluded. Reload source replaces the entire package and confirms replacement of all unexported edits. Comparisons use exact source ZIP snapshots and SHA-256 fingerprints of decompressed bytes, excluding ZIP metadata changes and local edits. Run `npm run test:source-changes` with Node.js 22.6+ for comparison and tree tests.
- **Source monitoring:** Click-to-open uses `showOpenFilePicker` when available; drops use `getAsFileSystemHandle` when available. Read-only handles use FileSystemObserver when available, with stability checks after events; missing or failed observers fall back to sequential 1.5-second polling. Detection never automatically replaces the open package. The status below the filename shows updates and a Reload action. Reload reads a fresh snapshot, preserving the viewed part, XML position and search state where possible. Unexported edits require confirmation before replacement; cancelling keeps all edits and pending updates. Temporary file-check failures retry, permission loss pauses monitoring, and closing/replacing the file stops it. Unsupported browsers still open normally, with monitoring unavailable shown. Handles remain in memory; no disk writes or extra server access are used. Settings uses Save to persist drafts; Close, Escape and the backdrop discard them.
- **Open OOXML:** Drop a file anywhere on the upload page (the upload card highlights), or click the card to choose XML-based Office packages using the same OPC relationship rules. PowerPoint: `.pptx`, `.pptm`, `.potx`, `.potm`, `.ppsx`, `.ppsm`, `.ppam`; Word: `.docx`, `.docm`, `.dotx`, `.dotm`; Excel: `.xlsx`, `.xlsm`, `.xltx`, `.xltm`, `.xlam`; themes: `.thmx`. Legacy `.ppt`, `.doc`, `.xls`, binary `.xlsb`, ODF and EPUB are excluded. Macro payloads remain binary and are preserved during repacking; they are not executed. Format scope follows [Microsoft’s XML extension reference](https://learn.microsoft.com/en-us/office/compatibility/xml-file-name-extension-reference-for-office).
- **Binary files:** Unsupported binary parts show a generic file icon, filename and preview-unavailable message, with the path and Relations toolbar. Their original bytes are preserved on export.
- **Office themes:** Open `.thmx` packages to browse and edit theme XML and relationships, preview thumbnails, and preserve embedded fonts and other binary resources when saving as `.thmx`.
- **File tree:** Left sidebar shows entries as a folder tree; expand/collapse with › indicator.
- **Find files:** Filter file names without case sensitivity, retain parent folders, clear the filter with Escape, or collapse all folders outside filtering mode.
- **Editor / preview:** Right side shows XML editor for text parts, image preview for `/media/` and image extensions.
- **XML validation and file revert:** After 450 ms without typing, XML parts are checked for well-formedness. The editor footer shows errors with a clickable line/column location when the browser provides it. This does not validate Office schemas. Revert current file restores its last export baseline after confirmation, preserves other files, and can itself be undone.
- **Inline diff:** Editing XML automatically shows deleted original lines in red and current additions in green, with character-level highlights. The Diff toggle hides or shows the comparison without changing content or undo history. Its global preference is saved locally across file navigation and reloads (enabled by default), with a shaded button when enabled. Diff controls appear in a compact editor footer only when the current file has changes, leaving the path toolbar for navigation and formatting. When enabled, Changes shows the number of changed blocks; Previous/Next buttons center each change, unfold its containing region, and wrap at either end. The label shows the current change when the cursor is inside one. Each diff block has a Revert button that restores only that block; the revert itself can be undone with Cmd/Ctrl + Z. Deleted lines are display-only. Comparison uses the current export baseline (initial formatting is excluded), and successful downloads update it.
- **Editor search:** A custom compact search bar shows the selected match index and total, with navigation outside the field and case/whole-word/regex toggles inside it. The optional replacement field aligns with the search field and has icon actions for Replace and Replace all; read-only source diffs omit replacement controls. Enter/Shift+Enter navigates, Escape closes. Invalid expressions and zero matches are explicit. Count bookkeeping is capped at 10,000 matches (shown with +), while native search navigation remains unrestricted. Switching files preserves the search panel, query, replacement text, and search options, and recalculates matches in the new document. Search state stays in memory for the open package and resets when it is closed or replaced.
- **XML navigation:** Hover over relationship IDs or internal file paths in XML attributes to preview the target. Cmd/Ctrl + click opens the file; ordinary clicks continue editing. The hover preview also offers a clickable target. Only existing package files are opened; external relationships are excluded.
- **Relations:** The path toolbar groups internal related parts under “Relations ↑outgoing ↓incoming”, with matching arrows in References and Referenced by section headings. Both directional counts include zero; external links are excluded. Hover to open a right-aligned list of related files; moving into the list keeps it open. Enter or Arrow Down also opens it for keyboard navigation. Click a file to navigate; move away, click outside, or press Escape to close.
- **Edit & download:** Edit XML in place with undo/redo; "Download" repacks the ZIP into a new file. Unexported changes are marked in the tree and header, with a discard confirmation before closing or replacing the file and a browser warning before leaving the page.
- **Download shortcut:** Use `⌘S` on macOS or `Ctrl+S` on Windows/Linux to export changes. With no changes, a notice appears instead of downloading again. Shortcuts are suppressed while a dialog is open or an export is in progress.
- **Dev:** In development, the first `.pptx` in `public/` is auto-loaded on start (port 8800).

## UI Overview

- **Empty state:** Centered document/code logo, “OOXML Viewer” title, short description, and a drop zone listing supported formats; dashed border and hover highlight. The logo also serves as the browser favicon.
- **With file open:**
  - **Header:** File name and unexported change count on the left; “Download” and “Close file” on the right; Settings is at the bottom of the sidebar and contains the GitHub link.
  - **Left panel (Files):** Tree with “Files” title; folders use › (rotates 90° when expanded), fixed-width chevron column; files show name; selected row highlighted; independent scroll.
  - **Right area:** Path bar at top; below either XML editor (monospace, editable for non-binary) or image preview (centered, contained); independent scroll.
- **Styling:** UnoCSS; warm neutral palette; rounded controls; minimal margins (global reset on `html`/`body`/`#app`).

## Tech

- Svelte 4, TypeScript, Vite 6, pnpm, UnoCSS, JSZip.

The inline diff uses the official CodeMirror `@codemirror/merge` package, pinned to `6.12.3` from the npm registry; its dependency integrity is recorded in `pnpm-lock.yaml`. It runs locally and does not upload document content.

## Code organization

- `sourceFile.ts` acquires read-only handles and watches for stable disk changes. `sourceSession.ts` owns monitoring state, comparison snapshots, retries, reload lifetimes and stale-result rejection; App owns confirmations and applying the result to the editor.
- `packageIndex.ts` owns stable file-tree metadata and internal relationship indexes. Editing ordinary XML leaves these untouched; editing a `.rels` part reparses and replaces only that part's relationships.
- `partContent.ts` shares XML/RELS/VML classification, UTF-8/BOM-marked UTF-16 decoding and formatting between opening and source comparison.
- `editorPresentation.ts` shares CodeMirror presentation, search styling and reading-position helpers. `XmlEditor` owns editing/undo/validation; `SourceDiffPanel` owns the read-only source comparison.
- `styles/buttons.css` provides opt-in button classes; custom controls and CodeMirror style their own buttons.

Run `npm test` (Node.js 22.6+) for source monitoring, session concurrency, source comparison, index invalidation, text decoding, settings and route-history tests. UI flow verification also covers local edits alongside disk updates, source-diff history navigation, cancelling reload and applying a confirmed reload.
